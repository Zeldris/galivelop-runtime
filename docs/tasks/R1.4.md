# R1.4 — Worker

**Estado:** hecho, sin revisar (2026-11-27) · **Fase:** `0.1` (R1) · **Presupuesto de compactaciones:** 0

El worker genérico de `grun`: reclama, toma el candado de máquina, desaloja Ollama, espera memoria, ejecuta el motor
y cierra la entrada sin lanzar nunca una excepción. Fuentes (se leen, no se tocan; en `/home/user/zeldris/`):

## Qué entra

Solo stdlib y `grun.*`; ningún módulo importa nada de una aplicación.

### `grun/engine.py`: la interfaz del motor (D-9)

```python
@dataclass
class Job:
    entry: dict      # copia de la entrada (campos de la aplicación incluidos: kind, take…)
    machine: dict    # el perfil de máquina ya cargado

class Engine(Protocol):
    def run(self, job: Job, on_progress, should_cancel, pass_fds: tuple): ...   # -> Result (lo que quiera la app)
    # opcional: def min_free_memory_mb(self, job: Job) -> int | None   (umbral por modelo, como gimg)

class EngineError(Exception):   # EngineError(message, code=None, **params)
class EngineTimeout(EngineError)
class Cancelled(Exception)
```

- `on_progress(progress)`: `{step, steps, etaS}` va a `Queue.set_progress`; si trae `preview` (ruta), además
  `Queue.set_preview`. Los errores de la cola se tragan (el progreso es informativo).
- `should_cancel()`: `Queue.is_cancel_requested(id)`.
- `pass_fds`: `machine_lock.held_fds()`. El motor lo pasa a su `Popen` (invariante 3).
- gvoice despacha sus operaciones (`design`, `line`, `voiceprint`) por `job.entry["kind"]` dentro de su `run`:
  eso es de gvoice (R3), no de `grun`.

### `grun/ollama.py`: desalojo (D-7) y comprobación de host (invariante 11)

Lo de gimg (`ollama_loaded`, `ollama_unload`, la espera), sin dependencias de gimg:

- `check_local(url) -> str`: solo `http`/`https` (otro esquema: `engine.ollama_url`) y host `localhost`,
  `127.0.0.1` o `::1` (otro: `net.non_local_host`, con `host`). Devuelve la URL sin `/` final.
- `loaded(url, timeout=2.0) -> list[str]`: `GET /api/ps` sin proxy (`ProxyHandler({})`), máximo 1 MiB; nombres con
  `size > 0`. Cualquier error de red o JSON: `[]`.
- `unload(url, name, timeout=10.0)`: `POST /api/generate` `{"model", "keep_alive": 0}` y `POST /api/embed`
  `{"model", "input": "", "keep_alive": 0}`; errores ignorados.
- `evict(machine, should_cancel=None, *, wait_s=15.0, poll_s=1.0) -> list[str]`: modo `machine["engine"]["ollama"]`
  = `unload` (por defecto, D-7) | `abort` | `ignore`; URL `GRUN_OLLAMA_URL`, si no `engine.ollamaUrl`, si no
  `http://localhost:11434`, siempre por `check_local`. `unload`: descarga cada modelo cargado y sondea `loaded` hasta
  vacío o `wait_s`; lo que siga cargado, `GrunError("engine.ollama_loaded", models=…)`. `abort`: con modelos
  cargados, ese mismo error sin descargar. `ignore`: nada. La espera llama a `should_cancel` en cada vuelta y lanza
  `machine_lock.WaitCancelled` (es una espera, invariante 4). Devuelve los modelos descargados.
- Nota para R4: el perfil de gimg trae `engine.ollama: "abort"`; si gimg quiere el nuevo defecto, lo quita.

### `grun/profile.py`: `ProfileLoader` (D-12)

```python
load_profile(ref=None, *, presets: Path, env_var: str, config_path: Path | None = None,
             default="steam-deck", validate=None) -> dict
```

Orden de gimg/gvoice: `ref`, si no `$<env_var>`, si no `machineProfile` de `config_path` (JSON), si no `default`.
Con `/` o terminado en `.json` es una ruta; si no, un nombre (`^[a-z0-9][a-z0-9-]*$`, si no `machine.bad_name`) que
se lee de `presets/<nombre>.json`. Errores: `machine.missing` (no existe), `machine.unreadable` (no se puede leer o
no es JSON), `machine.invalid` (con `errors`). `grun` comprueba solo lo que usa: `timeoutS` entero > 0 (obligatorio),
`minFreeMemoryMb` y `watchMemoryMb` enteros ≥ 0 si están, `engine` objeto si está, `engine.ollama` en
`unload|abort|ignore` y `engine.ollamaUrl` cadena si están. Lo demás se conserva tal cual. `validate(profile)` es el
esquema completo de la aplicación (puede lanzar su `GrunError`). Códigos `machine.*` nuevos en `grun`: se conservan
los nombres de gimg (D-14), con texto en `en` y `es`.

### `grun/worker.py`: `Worker`

```python
Worker(queue: Queue, engine: Engine, *, app: str, load_profile, order_store=None, log_path=None,
       lang=None, memory_poll_s=0.5)
Worker.run(once=False) -> int        # entradas tratadas; nunca lanza salvo worker.already_running
Worker.run_once() -> bool            # una entrada (False si no había ninguna); para tests y para `run`
```

- **`worker.lock`** (`paths.worker_lock_path`): exclusivo con reintento corto, **nunca un solo `LOCK_EX|LOCK_NB`**
  (las lecturas con recuperación y `worker_alive` toman un `LOCK_SH` momentáneo; observación de la revisión R1.2+R1.3):
  reintenta cada 0.02 s hasta 0.3 s; si entonces solo lo tienen sondeos (`LOCK_SH|LOCK_NB` sale bien), sigue
  reintentando hasta 5 s (como `_only_probes` de gimg); si no, `GrunError("worker.already_running", path=…)`. Se
  suelta al salir de `run`. El archivo no se borra nunca (invariante 5).
- **Señales:** dentro de `run`, SIGTERM y SIGHUP pasan a `SystemExit(128+sig)` para que corran los `finally`; se
  restauran los manejadores al salir. La entrada que corría se queda en `running` y la recupera el siguiente worker.
- **Bucle:** `queue.recover_orphans()`; luego `claim()` hasta `None` (`claim` ya respeta la pausa y `held`), sin espera
  ociosa: con la cola vacía, `run` termina. `once=True`: una entrada como mucho.
- **Una entrada, en este orden** (DDD §4, «Orden dentro de un titular»):
  1. `profile = load_profile()`; un error aquí cierra la entrada como `failed` con su código.
  2. **Intento ya hecho (invariante 9):** si `order_store` y `order_store.attempt_for_entry(entry)` devuelve un id,
     `finish(id, "done", attempt_id=…)` sin tomar el candado ni llamar al motor.
  3. `machine_lock.hold(should_cancel, on_wait, app=app, entry=id)`; dentro:
  4. `ollama.evict(profile, should_cancel)`;
  5. espera de memoria (D-8): umbral `engine.min_free_memory_mb(job)` si el motor lo tiene y no da `None`, si no
     `minFreeMemoryMb` del perfil; con `limits.available_memory_mb()` cada `memory_poll_s`, sin tope de tiempo;
     `worker.waiting_memory` a stderr una vez; `should_cancel()` → `WaitCancelled`. Memoria ilegible (`None`) pasa.
  6. `result = engine.run(job, on_progress, should_cancel, machine_lock.held_fds())`;
  7. si después `should_cancel()` es verdad: `Cancelled`.
  8. `attempt_id = order_store.add_attempt(entry, result)` si hay `order_store` (idempotente por entrada); se cierra
     `done` con ese `attempt_id`.
- **Errores → entrada** (`_error_for`, como gimg/gvoice): `Cancelled` y `WaitCancelled` → `cancelled` (la cola lo
  acepta porque `cancelRequested` está puesto; si no lo estuviera, `failed` con `worker.unexpected`); `GrunError` →
  su código y parámetros; `EngineTimeout` → `engine.timeout`; `EngineError` con código → ese código; sin código →
  `engine.failed {message}`; cualquier otra `Exception` → `worker.unexpected {message: "Tipo: texto"}`.
  `KeyboardInterrupt`/`SystemExit` no se capturan. `finish` que falla: `worker.finish_failed` a stderr y se sigue
  (la recuperación lo arreglará).
- **Eventos** (DDD §4; líneas JSONL con `log.append` en `log_path`, si lo hay, best effort: un fallo escribe
  `worker.log_failed` a stderr): `EntryClaimed`, `LockWaited` (al empezar a esperar), `LockAcquired` (con `waitedMs`),
  `OllamaEvicted` (con `models`, solo si descargó alguno), `MemoryWaited` (con `waitedMs`, solo si esperó),
  `EntryFinished` (con `state` y `error.code`) y `OrphanRecovered` (uno por entrada recuperada al arrancar). Forma:
  `{"event", "app", "entry", "at", …}`. Al cerrar, además una línea `{"schema": "grun.run/0", "app", "entry",
  "state", "errorCode", "lockWaitMs", "memoryWaitMs", "runMs"}` (D-13: `/0`, provisional).

## Fuera (otras tareas)

- El lanzador (`maybe_launch`, D-11): a pendiente; gimg lo usa desde R4.
- `EntryQueued`: lo emite quien encola (la cola no tiene `log_path`); a pendiente si hace falta en la cola.
- El vigilante de memoria durante la ejecución (`watchMemoryMb`, `limits.must_abort`) y el tope de tiempo
  (`timeoutS`): son del motor, que tiene el proceso.
- Borrar archivos a medias tras un fallo: del motor o del `PendingCleaner`.
- El turno de Ollama para procesos que no son Python (`ollama.generate` dentro de `hold`): `0.4` (R5).

## Tests

`tests/test_engine.py` (poco), `tests/test_ollama.py`, `tests/test_profile.py`, `tests/test_worker.py`, con motores y
`OrderStore` falsos, `GALIVELOP_STATE_HOME` y `<data>` en carpetas temporales, `GRUN_MEMINFO` para la memoria y un
servidor HTTP falso en `127.0.0.1` (hilo, `http.server`) para Ollama. Cada test que espera un error comprueba su
código.

- **Invariante 4 (cola):** candado tomado por otro proceso, cancelar la entrada mientras espera: queda `cancelled`
  (no `failed`), el motor no se llama y el candado sigue libre para este proceso. Lo mismo con la memoria por debajo
  del umbral y con `evict` esperando a un Ollama que no descarga.
- **Invariante 9 (motor):** entrada `running` sin worker; `run()` la recupera y, con un `OrderStore` falso cuyo
  `attempt_for_entry` ya da un id, el motor se llama 0 veces y la entrada queda `done` con ese `attemptId`.
- **Invariante 11 (cliente de Ollama):** `GRUN_OLLAMA_URL=http://example.com:11434` → `net.non_local_host`;
  `ftp://localhost` → `engine.ollama_url`.
- **Invariante 3, por el worker:** el motor recibe en `pass_fds` los descriptores de `held_fds()` (el test de
  proceso hijo ya está en `test_machine_lock.py`).
- Orden dentro del titular: evict → memoria → motor, con el candado tomado en los tres (`machine_lock.busy()` visto
  desde otro proceso, o `held_fds()` no vacío).
- Desalojo: `unload` descarga y espera; `abort` con modelos → `engine.ollama_loaded` y la entrada `failed`; `ignore`
  no llama; Ollama apagado (conexión rechazada) → nada cargado, sigue.
- Errores → códigos: `EngineError` con y sin código, `EngineTimeout`, excepción cualquiera, `GrunError` del perfil.
- `worker.lock`: con otro proceso que lo tiene exclusivo → `worker.already_running`; con un sondeo `LOCK_SH` que lo
  suelta enseguida → el worker lo toma.
- Progreso y vista previa llegan a la cola; un `set_progress` inválido no tumba la entrada.
- Pausa: `run` no reclama nada; `once`; cola vacía → `0`.
- SIGTERM durante el motor (subproceso): la entrada sigue `running` y el siguiente `run` la recupera.
- Eventos y línea `grun.run/0` en `log_path`; `log_path` no escribible → la entrada se cierra igual.
- `ProfileLoader`: orden de resolución, nombre malo, ruta, ausente, JSON roto, campos inválidos, `validate`.
- Textos nuevos (`machine.*`, `engine.ollama_loaded`, `engine.ollama_url`) en `en` y `es`: el test de locales que
  ya exista los cubre (si no, uno que compare claves).
