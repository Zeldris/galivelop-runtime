# R5 — Protocolo `grun.lock/1` para clientes que no son Python

**Estado:** parte de este repo hecha (2026-11-27) · **Fase:** `0.4` (R5) · **Presupuesto de compactaciones:** 0

DDD D-3 y D-13: WMF (`ollamaQueue.ts`) pasa por el candado de máquina lanzando `flock(1)` como proceso hijo dentro de
su cola de Ollama, con un tope igual a `queueTimeoutMs`, y `grun.lock` pasa a `/1`.

## Qué entra (este repo)

- `docs/protocol/grun.lock.1.md`: ruta, ejemplos con `flock(1)` (espera, no bloqueante, tope, cancelación), registro
  del titular, paso de `/0` a `/1`, comportamiento ante fallos e invariantes de un cliente no Python. Solo describe lo
  que hace hoy `grun/machine_lock.py`.
- `grun/machine_lock.py`: `SCHEMA = "grun.lock/1"`. Solo cambia el valor de `schema`; los campos no cambian.
- `schemas/grun.lock.1.json`: JSON Schema del registro (provisional, sin huella; D-13).
- `tests/test_lock_protocol.py`: el registro real de `hold()` valida contra el esquema; un `flock(1)` real (se omite
  si no está instalado) y `hold()` se excluyen en las dos direcciones, con espera cancelable.

## Cómo se comprueba

El test del esquema falla sin el cambio de `SCHEMA` (`red-without-fix.sh`). Los de `flock(1)` describen
comportamiento que `grun` ya tenía: no pueden ir en rojo sin un arreglo, no hay arreglo que quitar.
