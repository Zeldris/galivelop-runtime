# R3.1 — `grun vendor`

**Estado:** hecho, sin revisar (2026-11-27) · **Fase:** `0.2` (R3) · **Presupuesto de compactaciones:** 0

DDD §0 («Cómo lo usan»): un consumidor en Python vendoriza `grun` con su versión y un test que compara su huella
sha256. Esta ficha es la herramienta de este repo; lo que se cambia en gvoice (borrar sus copias, vendorizar, retirar
el script de desalojo) no se toca desde aquí.

## Qué entra

`grun/vendor.py`, solo stdlib y `grun.*`:

- `collect(root)`: `{ruta: sha256}` de `*.py` y `locales/*.json` (archivos normales; nunca `__pycache__` ni el manifiesto).
- `fingerprint(files)`: un sha256 sobre las líneas `ruta NUL sha256 LF` ordenadas.
- `export(dest, source=None)`: copia el paquete a `<dest>/grun` y escribe `VENDOR.json` (`grun.vendor/0`: versión,
  `source` = sha corto de git con `-dirty` si hay cambios, huella y lista de archivos). Una `<dest>/grun` que ya
  existe se reemplaza solo si es una copia vendorizada (tiene manifiesto); si no, `vendor.not_vendored` y no se toca nada.
- `verify(root, pinned=None)`: `[]` si la copia está intacta; si no, problemas `{code, params}` por archivo
  (`vendor.missing`/`changed`/`extra`), `vendor.fingerprint` (manifiesto retocado para esconder un cambio),
  `vendor.pinned` (la huella no es la que fijó el consumidor), `vendor.no_manifest`/`bad_manifest`.
- `python -m grun vendor (--dest DIR | --verify DIR [--pinned SHA256]) [--json]`: salida 0/1/2.

El test del consumidor llama a `grun.vendor.verify(<su grun>, pinned=<huella fijada>)` y espera `[]`.
